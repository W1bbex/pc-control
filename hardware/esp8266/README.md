# Диагностика ESP8266

Прошивка `pc_remote_mqtt` управляет реле и подключается к MQTT по TLS.

## Инцидент 09.11.2026

По журналу Mosquitto: таймауты ESP в 01:18:16, 01:20:22 и
01:21:58 (МСК). Следующее успешное MQTT-подключение — 15:16:54.
Сервер и брокер в этот промежуток не перезапускались.
Первопричина не установлена: прежняя прошивка не передавала состояние
Wi-Fi, ошибки TLS, память и причину сброса. Исторический Serial-вывод не сохранялся.

## Восстановление и журнал в версии 2.1

- Обычные повторы MQTT — раз в 3 с, Wi-Fi — раз в 15 с.
- После 120 с без MQTT — закрытие сокета и повторное подключение Wi-Fi.
- После 300 с без MQTT — перезапуск ESP с предварительным отпусканием реле.
  Сброс сети и перезапуск откладываются на время активного импульса реле.
- Счётчик сбрасывается после рабочего MQTT-соединения. Разность `millis()`
  вычисляется без знака для корректной работы при переполнении.
- DNS разрешается отдельно с таймаутом 1500 мс; ошибки DNS, MQTT, TLS,
  нехватка памяти и причина отключения Wi-Fi записываются отдельно.
- Два файла LittleFS по 12 КБ сохраняют события после отключения питания.
  При невозможности монтирования раздел инициализируется заново; повреждённый
  журнал при этом теряется. Конфигурация EEPROM находится отдельно.
- При подключении журнал отправляется на сервер по одной строке за итерацию.
  Используется существующий разрешённый топик `pc/main/esp/status`, без retain.
  События не изменяют онлайн-статус. Доставка QoS 0: локальные файлы сохраняются,
  при следующем подключении отправка повторяется, поэтому возможны дубликаты.
- Heartbeat раз в минуту содержит версию, uptime, свободную память,
  максимальный свободный блок и RSSI. Идентификатор загрузки случайный.
- Секреты и SSID в диагностические сообщения не включаются.

На VDS искать `ESP diagnostic` и `ESP status` в журнале `pc-control-bot`.
Для автономной диагностики читать Serial на 115200 бод. Если сервер недоступен,
журнал останется во flash до восстановления связи или ротации.
Программное восстановление не устраняет неисправность питания или оборудования.

## Сборка и проверка

Из корня репозитория: `arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 hardware/esp8266/pc_remote_mqtt`.
Проверки шлюза: `.venv/Scripts/python.exe -u -m pytest tests/test_esp_diagnostics.py vds_bot/test_health_engine.py -q`.
Перед записью сохранять полный образ flash; не использовать `erase-all`, чтобы
сохранить EEPROM. После прошивки проверить версию и загрузочные события на VDS.
